# Evidence and Analysis

## Decide from the exchange

A confirmed case shows the user could not identify the meaning, referent,
reasoning or relevance of an assistant answer. Read enough context to establish
that relationship. Profanity, disagreement, a new factual question, frustration
at failed execution and a request for proposals are not sufficient by themselves.
Keep uncertain cases ambiguous; do not inflate the count after user criticism.

Resolve the challenged passage from annotation or quote evidence first, then
the conversation sequence. Note any unavailable original answer. For numbered
messages, cite the particular qualifying item and exclude unrelated items from
the causal explanation. Literal matches inside copied assistant text, injected
instructions or metadata are not user misunderstanding signals.

Review signal-free user messages too. Mark ordinary messages as swept, and add
semantic candidates using the same evidence standard. Record the selection
method separately from the decision so search recall can be checked.

## Find the missing connection

Describe the actual missing bridge in the user's vocabulary: which thing or
actor, belonging to which task, doing what, where, for what purpose, and how it
answers the question. Identify the unexplained assumption or causal step rather
than calling the answer too short. Check whether the assistant confused a fact,
a completed change or a proposal, or described a workflow the user never needed.

Follow each clarification until the topic changes or the available exchange
ends. Record which connection it repaired or left unresolved, and whether it
introduced another term, analogy, premise or proposal. Preserve the original
question across the chain. A later What is a separate message in the same
episode, not a duplicate of the earlier What. Lack of another objection is not
positive evidence of understanding.

Separate inaccurate claims from wording problems. A fluent rewrite cannot
repair a false claim; a simpler report cannot justify unnecessary work. Draft
a better answer from facts demonstrably available at the failing turn, with
only the background needed for the connection. Label anything that would have
required verification then instead of silently importing hindsight.

## Select the correct owner

Inspect current rules and relevant recorded instructions separately. A rule
present in a session is evidence that it was supplied, not proof it was followed
or that attention to it caused the failure. When the recorded stack is missing,
do not infer that today's rule was active then.

Compare a wording/rule repair with an intervention in the report template,
helper result or workflow decision that produced the confusion. A repeated
equivalent global rule is not a remedy for an existing rule ignored. Recommend
an exact owner and the smallest change that would prevent the observed failure;
retain correct brevity, technical accuracy and authorization boundaries.

For each recommendation, state the deciding evidence, the alternative rejected,
the regression example and remaining uncertainty. Exact instruction proposals
must use the governance workflow; an audit does not authorize implementation.
History-wide semantic review costs more as N and message volume increase. Keep
deterministic work in the helper and use the single-case mode for narrow repair.
