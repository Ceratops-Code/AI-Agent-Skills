# Change Promotion Action

## Goal

Promote committed skill branches into a compatible skill repo checkout's local
release branch so Codex can use one coherent unpublished repo snapshot. Update
installed runtime only when this action is intentionally selected.

## Context

### Defaults

- Source repo: active skill repo checkout root
- Installed managed skill path: `$CODEX_HOME/skills/<skill-name>`
- Default release branch: `release/local`
- Default remote: `origin`
- (D) Repository installer: `python scripts/install-skills.py`, which uses the
  supported installed lifecycle bundle and permits target-checkout fallback
  only for the initial Ceratops installation.

### Script Bundle

- (D) Promotion and installation helper from the selected lifecycle bundle:
  `scripts/promote-skill-branches-to-release-and-install.ps1
  -SkillsRepoRoot <repo> -ApprovedBranch BRANCH [-ApprovedBranch BRANCH...]
  -MainBranch main -ReleaseBranch release/local -RemoteName origin`.
- (D) Release branch preparation:
  `scripts/prepare-release-branch.ps1
  -SkillsRepoRoot <repo> -MainBranch main -ReleaseBranch release/local
  -RemoteName origin` from the selected lifecycle bundle.
- (D) Approved-source check and terminal cleanup:
  `scripts/check-pending-release-work.ps1 -SkillsRepoRoot <repo>
  -ApprovedBranchData <approved-branch-payload>
  -PromotionCommit <promoted-head> -RecordPromotion` during promotion, then
  `-PromotionCommit <promoted-head> -CleanMergedBranches` only after terminal
  remote shipping.

### Inputs To Capture

- Committed task branches ready to join the local batch.
- Skill repo checkout path and intended local `release/*` branch.
- Whether the release branch should append more branches or be rebuilt manually
  before staging.
- Dirty or unmerged state in the approved branches or their worktrees.
- Local validation expectations for the staged batch.
- Target repository compatibility manifest and selected lifecycle helper
  bundle.

Infer missing inputs from local repo state before asking.

## Constraints

### Boundaries

- Use this action when the goal is coherent local preview or local batching of
  unpublished skill changes in a skill repo checkout.
- If the task is creating or updating skill source and not yet staging it,
  return to the parent skill and select `create` or `update`.
- If the skills repo release branch is already staged or the task is general
  repo shipping, return to the parent skill and select the owning action.

### Workflow

#### 1. Inspect source and skills repo state

- Inspect approved source worktree branches, the skill repo checkout branch,
  installed managed skill-copy state when applicable, and duplicated installed
  copies when that runtime exists.
- Do not inspect unrelated worktrees or branches during promotion.
- Confirm each branch to stage is intentionally committed and available to the
  shared repo.
- Refresh remote refs with `git fetch --prune origin` before judging remote
  release branch state or cleanup.
- Reuse an existing local release branch without merging current `main` into
  it; create a missing release branch from refreshed `main`.
- If a branch already shipped through a squash merge, recreate or rebase it on
  current `main` before staging more work from it.

#### 2. Stage the release branch

- Before promoting each requested task branch, run a blocking local code review
  against current release branch state.
- (D) Run `promote-skill-branches-to-release-and-install.ps1` with only
  branches that passed the blocking review; it owns release-branch preparation,
  `git diff --check (git
  merge-base HEAD BRANCH) BRANCH`, fast-forward-only branch promotion,
  repository-configured mypy validation, one approved-source pending-work check
  and exact promotion retention record after all approved branches are promoted
  and before profile-aware full validation and runtime installation, and compact
  ready/not-ready output.
- The helper must stop unless the current release `HEAD` is an ancestor of each
  approved branch; rebase a divergent task branch onto the release branch in
  its task worktree before promotion.
- Stop if the installed lifecycle bundle lacks the promotion helper or the
  target repository lacks `scripts/install-skills.py`.
- If the skills repo checkout is dirty before staging, stop instead of
  promoting into it blindly.

#### 3. Validate and install staged state

- (D) Treat the promotion helper's successful `validation` and `install`
  fields as the mypy, full-validation, and install result.
- Confirm each installed managed skill copy has
  `.runtime-manifest.json` and was regenerated by the installer when
  the repo uses managed runtime copies.
- (D) When the PR-workflow package or installer changed, run
  `python -m github_pr_workflow validate --help` from
  `skills/ceratops-gh-repo-lifecycle/scripts`.

#### 4. Report staged state

- Retain clean approved task worktrees and branches through remote review;
  report the exact promotion commit and retention record needed for terminal
  cleanup.
- If the pending-work check reports dirty or unmerged approved work, stop before
  installation.
- Report active local `release/*` branch, staged task branches, and blockers
  that still prevent shipping.

## Done When

### Completion Gate

- The skill repo checkout is on the intended local `release/*` branch.
- Every branch promoted into the staged branch had a clean blocking local code
  review against the then-current release branch.
- Requested task branches were staged; their clean source worktrees and branches
  were retained by exact promotion commit for terminal remote-shipping cleanup,
  while dirty or unmerged approved sources block installation.
- Unrelated local branches and worktrees were not inspected, modified, or
  removed.
- Installed skill copies are managed runtime outputs with fresh runtime
  manifests when the repo uses managed runtime copies.
- Local validation batch passed or blocking failures were reported when
  validation exists.

### Output Contract

Report only:

- active local release branch and staged task branches
- unresolved blockers or non-blocking debt
- intentionally retained skills repo state, branches, or worktrees with reasons
- anything important not verified
